## Summary

- Engineered a fully decoupled backend using **Clean Architecture** and **Domain-Driven Design (DDD)**, separating domain logic, use cases, infrastructure adapters, and the API presentation layer into independent, interchangeable modules.
- Built a non-blocking, asynchronous job queue architecture to handle intensive AI inference (Surya OCR) without freezing the API, with fine-grained per-page cancellation and retry support.
- Delivered a highly interactive, dark-themed React 19 interface with real-time WebSocket log streaming, synchronized bounding-box rendering, and a gradient-based OCR confidence map.
- Implemented heuristic reading order detection and geometric data analysis to automatically extract and apply style metadata (bold, italic) to semantic blocks.
- Produced accessibility-grade **Semantic PDF** exports: logically ordered, hyphen-resolved, and screen-reader-optimized output going beyond simple text-layer PDFs.

## Overview

Restora is an AI-powered system specifically designed for the digitization and structural analysis of physical book pages. Existing solutions often struggle with complex document layouts, multi-column arrangements, and accessibility of the resulting digital output. Restora addresses these gaps by combining advanced OCR, coordinate-based layout analysis, and heuristic reading order detection to convert scanned pages into structured, searchable, and accessibility-grade digital formats.

The system provides a fully localized, end-to-end ecosystem from raw image upload through OCR processing, interactive document inspection, to multi-modal PDF export without relying on any cloud OCR service.

## Architecture & Data Design

The backend is structured around **Clean Architecture** and **Domain-Driven Design** principles, ensuring that core business logic is fully insulated from framework, database, and OCR library concerns.

### Layered Structure

- **Domain Layer:** Contains pure Python entities (`Document`, `Page`), value objects (`DocumentStatus`, `OCRResult`, `LayoutData`), domain exceptions, and abstract port interfaces (`IDocumentRepository`, `IFileStorage`, `IOCREngine`, `ITaskQueue`, `INotificationService`). No external dependencies.
- **Application Layer:** Orchestrates use cases (`UploadDocumentUseCase`, `ProcessPageUseCase`, `ReprocessDocumentUseCase`, `GetDocumentUseCase`, `ListDocumentsUseCase`, `DeleteDocumentUseCase`) exclusively through domain entities and abstract ports.
- **Infrastructure Layer:** Provides concrete adapter implementations `SqliteDocumentRepository`, `LocalFileStorage`, `SuryaOCREngine`, `AsyncProcessingQueue`, and `WebSocketNotificationService`. Swapping any of these (e.g., replacing SQLite with PostgreSQL) requires no changes to domain or application code.
- **API (Presentation) Layer:** FastAPI routers handle HTTP and WebSocket requests, with all dependencies injected via `api/dependencies.py` factory functions using FastAPI's `Depends` mechanism.

### Data Persistence

A localized, auto-generated **SQLite** database stores books, pages, raw extracted text, and coordinate-based layout JSON. A `DatabaseMapper` converts between raw `sqlite3.Row` objects and domain entities, fully isolating schema changes from business logic. File assets (uploaded PDFs, rasterized page images, OCR JSON outputs) are organized under a `uploads/{job_id}/` hierarchy managed by `LocalFileStorage`.

### Tech Stack

- **Backend:** Python 3.10+, FastAPI, Surya OCR (PyTorch / Segformer models), SQLite, asyncio
- **Frontend:** React 19 (Vite), TypeScript, TailwindCSS, DaisyUI

## Key Features

### AI-Powered OCR & Layout Analysis

Restora uses the Surya OCR engine featuring Segformer-based segmentation models for high-accuracy text detection across multiple languages. Rather than producing flat text output, the engine extracts coordinate-based bounding boxes for every detected semantic block, enabling spatial reconstruction of the original document layout.

### Heuristic Reading Order Detection

A dedicated reading order algorithm analyzes the geometric positions of detected blocks to determine the logical flow of text handling multi-column layouts, sidebars, captions, and footnotes without relying on hardcoded structural assumptions. Style metadata such as font weight (bold) and posture (italic) are inferred from bounding box geometry rather than embedded font signals, making the system robust to scanned and photocopied sources.

### OCR Confidence Visualization

The document viewer integrates a gradient-based confidence map that overlays OCR certainty scores directly onto the line-level interface. This bridges raw model metrics with the user experience, allowing editors to immediately identify low-confidence regions and prioritize manual corrections.

### Dual-Layer Document Viewer

The interactive viewer provides two complementary visualization modes:

- **Line-based view:** Shows detected text lines with their spatial positions.
- **Semantic/geometric block view:** Groups lines into logical semantic blocks with full bounding box overlays.

In both modes, the image and text panels are synchronized hovering over a text segment highlights its physical location on the page image, and vice versa.

### Semantic PDF Export

Beyond standard searchable PDF generation, Restora produces a **Semantic PDF** export mode designed for accessibility:

- Text is written in **logical reading order** as determined by the heuristic detection algorithm, not in the visual scan order of the OCR engine.
- **Sentence-ending hyphens** (soft hyphens introduced by physical line breaks in printed books) are automatically detected and resolved, restoring words to their complete forms.
- The resulting PDF is structured for screen readers and assistive technologies, producing output that is near-ideal for visually impaired readers.
- Users can export the full document or any selected page range in either standard or semantic mode.

### Asynchronous Multi-Page PDF Processing

Users upload multi-page PDFs which are immediately split into individual page jobs and queued for parallel background processing. The API returns instantly with a `job_id`; pages are rasterized to high-quality PNG and processed through OCR independently, with real-time per-page progress broadcast over WebSocket.

## Technical Implementation

### Job Queue & Worker Architecture

Long-running OCR inference is handled by an `asyncio.Queue`-based worker pool (`AsyncProcessingQueue`) that is initialized at application startup. API endpoints such as `/upload-pdf`, `/document/{job_id}/cancel`, and `/document/{job_id}/retry-failed` allow fine-grained management of background tasks without blocking the request thread.

### Centralized Layout Engine

All spatial rendering mathematics used across both the interactive UI and the PDF generation pipeline are consolidated into a single reusable layout module. This ensures that font calculations, bounding box scaling, and block positioning remain consistent between what the user sees in the viewer and what is written to the exported PDF.

### Real-Time WebSocket Communication

Two WebSocket channels serve the frontend:

- `/api/v2/ws/progress/{job_id}` streams per-page processing updates (status transitions, progress percentage, OCR results) as JSON events.
- `/api/v2/ws/logs` broadcasts live system logs from the backend workers directly to the browser's log monitoring panel.

### Dependency Injection

All infrastructure adapters are instantiated as singletons via factory functions in `api/dependencies.py` and injected into use case constructors through FastAPI's `Depends` mechanism. Endpoints remain completely decoupled from concrete implementations.

### State Management (Frontend)

Global state is managed through React Context. The document viewer, confidence overlay, reading order display, and export controls share a unified state model, with WebSocket events updating page statuses reactively without requiring polling.

### Security Note

As Restora is designed as a localized tool running on `localhost`, complex authentication or RBAC mechanisms are intentionally outside the current scope.
