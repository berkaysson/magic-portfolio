## Summary

- Developed a scalable backend architecture using C# with ASP.NET Core 8 and Entity Framework Core.
- Eliminated vendor lock-in by abstracting the storage layer with an `IStorageService` interface and implementing self-hosted MinIO object storage.
- Optimized network I/O and server memory allocation by implementing Presigned PUT/GET URLs for direct client-to-storage media handling.
- Standardized the database layer by migrating from dynamic URLs to persistent GUID-based `AudioFileKey` structures in MSSQL.
- Containerized the entire ecosystem (API, UI, Database, and Object Storage) into an optimized multi-container environment via Docker Compose.
- Implemented robust health checks within the orchestration layer to ensure deterministic service startup sequencing.

## Core Features

- **Audio Streaming & Uploads**: Secure, direct media streaming and asset uploading using cryptographic presigned signatures.
- **Playlist Management**: Complete CRUD operations for custom user playlists, track discovery, and curation.
- **Identity & Access Management**: Secure user authentication and granular role-based access control (RBAC) powered by ASP.NET Identity and JWT tokens.
- **Responsive UI**: Single Page Application (SPA) dashboard designed for fluid playback controls, dynamic routing, and error interceptors.

## Architectural Architecture & Implementation

### 1. Storage Abstraction Layer

The application implements an infrastructure-agnostic storage layer. By enforcing the `IStorageService` contract, the underlying storage infrastructure can be swapped seamlessly without modifying core business logic. The current implementation utilizes an on-premise MinIO cluster operating over standard S3 protocols.

### 2. Presigned URL Streaming Mismatch Mitigation

Traditional media backends proxy heavy audio files through the application server, causing severe RAM utilization spikes and I/O bottlenecks. Harmonii circumvents this by using the backend solely as a control plane that issues short-lived Presigned URLs. The client directly uploads to and streams from the storage node, maximizing throughput.

### 3. Orchestration & Deterministic Networking

The platform is fully containerized to run identically in development and staging environments. To avoid race conditions where the API container boots before its database or storage dependencies are ready, Docker `healthcheck` parameters are explicitly bound to the `depends_on` lifecycle. Nginx handles frontend single-page application routing (`try_files`) and acts as the secure entry point.

## Technical Stack

- **Frontend**: React.js, React Router, Axios (with global response interceptors)
- **Backend**: ASP.NET Core 8, Entity Framework Core, MSSQL, ASP.NET Identity, JWT
- **Infrastructure & Devops**: Docker, Docker Compose, MinIO, Nginx
