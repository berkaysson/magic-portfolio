Kalıcı ve anlık bildirim sistemi kurmak gözünüzde büyümesin. Bu yazıda, üç basit adımda (Model, Backend Tetikleme, Real-time Abonelik) Next.js uygulamanıza nasıl ultra hızlı ve basit gerçek zamanlı bildirimler ekleyebileceğinizi göstereceğim. Prisma ve Supabase Realtime ile bu iş düşündüğünüzden çok daha kolay ve yönetilebilir.

## 1\. Veritabanı Modeli ve Backend Tetikleyicileri

### 1.1. Prisma Bildirim Modeli

Öncelikle, oluşacak bildirimleri depolamak için bir tablo yaratmamız lazım. Ben **Prisma ORM** kullanıyorum ve `notifications` tablosuna karşılık gelen aşağıdaki modeli oluşturdum. Uygulamamda bildirimler her bir randevu (`appointment`) oluştuğunda veya düzenlendiğinde tetikleniyor.

```typescript
enum NotificationType {
  APPOINTMENT_CREATED
  APPOINTMENT_CANCELLED
  APPOINTMENT_CONFIRMED
  APPOINTMENT_UPDATED
}

model Notification {
  id        String           @id @default(cuid())
  userId    String           @map("user_id")
  type      NotificationType
  title     String
  message   String           @db.Text
  read      Boolean          @default(false)
  
  appointmentId    String?  @map("appointment_id") // Randevu silinirse null olabilir
  organizationId   String   @map("organization_id")
  
  metadata  Json? // Ek veriler için
  
  createdAt DateTime         @default(now()) @map("created_at")
  readAt    DateTime?        @map("read_at")

  user         User          @relation(fields: [userId], references: [id], onDelete: Cascade)
  organization Organization  @relation(fields: [organizationId], references: [id], onDelete: Cascade)

  @@index([userId, read, createdAt]) // Kullanıcının okunmamış bildirimlerini getirmek için kritik
  @@map("notifications")
}
```

### 1.2. Backend Bildirim Oluşturma İşlemi

Veritabanı migration yapıldıktan sonra, her gerekli yere bildirim oluşturma işlemi yapıyoruz. Aşağıdaki örnekte bir randevu iptal edildikten sonra oluşan duyuru gösterilmiştir:

```typescript
// Randevu durumu CANCELLED olarak güncellenir.
await db.appointment.update({
  where: { id: appointmentId },
  data: {
    status: AppointmentStatus.CANCELLED,
    cancellationReason: cancellationReason || null,
  },
});

// Organizasyon sahibi ve üyelerine bildirim gönderilir.
const userName = appointment.user.name || appointment.user.email || "A user";
const formattedStartTime = appointment.startTime.toLocaleString();
const notificationTitle = "Appointment Cancelled";
const notificationMessage = `${userName} has cancelled the appointment "${
  appointment.title
}" scheduled for ${formattedStartTime} in ${appointment.organization.name}.${
  cancellationReason ? ` Reason: ${cancellationReason}` : ""
}`;

await createOrganizationNotifications(
  appointment.organizationId,
  appointment.id,
  NotificationType.APPOINTMENT_CANCELLED,
  notificationTitle,
  notificationMessage
);
```

Bu işlemden sonra `notifications` tablosunda yeni bir kayıt oluşur. Artık real-time (gerçek zamanlı) kısma başlayabiliriz.

## 2\. Supabase İstemcisi Kurulumu ve Abonelik

### 2.1. Supabase Client Oluşturma (Singleton Pattern)

Supabase SDK yüklemek ve bir client oluşturmak lazım. Burada **Singleton Pattern** kullanarak client'ın yalnızca bir kez oluşturulmasını sağlıyoruz. Supabase URL ve anon key, çevre değişkenlerinden alınabilir.

```typescript
import { createClient, SupabaseClient } from "@supabase/supabase-js";

// Client örneğini tutacak modül seviyesinde değişken
let supabase: SupabaseClient | null = null;

const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL;
const supabaseAnonKey = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY;

/**
 * Creates a Supabase client for client-side use.
 */
export const createSupabaseClient = () => {
  if (!supabaseUrl || !supabaseAnonKey) {
    throw new Error(
      "Missing Supabase environment variables: NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY are required"
    );
  }

  return createClient(supabaseUrl, supabaseAnonKey, {
    realtime: {
      params: {
        eventsPerSecond: 10, // Real-time olaylar için limit
      },
    },
  });
};

/**
 * Get a Supabase client instance (Singleton).
 * Bu, client'ı *sadece* ilk çağrıda oluşturur ve yeniden kullanır.
 */
export const getSupabaseClient = () => {
  if (!supabase) {
    supabase = createSupabaseClient();
  }
  return supabase;
};
```

### 2.2. Supabase Real-time Dashboard Ayarları (Zorunlu)

Abonelikten önce **Supabase Dashboard**'da `notifications` tablosu için şu işlemler yapılmalıdır:

1.  **Realtime'ı Etkinleştirin**: `notifications` tablosu için Real-time yayınını açın.
2.  **RLS (Row Level Security) Etkinleştirme ve Politika Oluşturma**:

    - RLS, kullanıcıların yalnızca kendi verilerini dinlemesini sağlamak için önemlidir.
    - Şimdilik hızlıca görmek için, **RLS'yi etkinleştirin** ve **geçici olarak tüm kullanıcılara erişim izni** veren bir okuma politikası kullanın.
    - **🚨 UYARI (Ürün Ortamı İçin KRİTİK):** Bu geçici politika **ASLA** canlıda (production) kullanılmamalıdır. Canlı uygulamada, yalnızca oturum açmış kullanıcının kendi bildirimlerini okumasını sağlamak için şu kısıtlı RLS politikası **zorunludur**:
    - Bu, yetkilendirme (Auth) olmadan başka bir kullanıcının verilerinin dinlenmesini engeller.

    ```sql
    create policy "Enable users to view their own data only"
    on "public"."notifications"
    as PERMISSIVE
    for SELECT
    to authenticated
    using (
        (select auth.uid()) = user_id
    );
    ```

### 2.3. Supabase Tablosuna Abone Olma Fonksiyonu

Oluşturulan Supabase client'ı kullanarak belirli bir kullanıcıya ait bildirim tablosuna abone olmamız lazım.

```typescript
// /data/subscribe-notifications.ts
"use client";

import { getSupabaseClient } from "@/lib/supabase";

export const subscribeToNotifications = (
  userId: string,
  onUpdate: () => void // Değişiklik olduğunda çalışacak callback
): (() => void) => {
  console.log("Subscribing to notifications for user:", userId);
  let channel: any = null;
  let supabaseInstance: ReturnType<typeof getSupabaseClient> | null = null;

  try {
    supabaseInstance = getSupabaseClient(); // Bu kullanıcıya ait bildirim değişikliklerine abone olunur.

    channel = supabaseInstance
      .channel(`notifications-${userId}`)
      .on(
        "postgres_changes",
        {
          event: "*", // Tüm olayları (INSERT, UPDATE, DELETE) dinle
          schema: "public",
          table: "notifications",
          filter: `user_id=eq.${userId}`, // Yalnızca ilgili kullanıcının ID'sine göre filtrele
        },
        (payload) => {
          console.log("Real-time notification update:", payload);
          onUpdate(); // Callback'i tetikle
        }
      )
      .subscribe(); // Temizlik fonksiyonu (Unsubscribe)

    return () => {
      if (channel && supabaseInstance) {
        supabaseInstance.removeChannel(channel);
      }
    };
  } catch (error) {
    console.warn(
      "Supabase not configured, real-time notifications disabled:",
      error
    );
    return () => {}; // No-op cleanup
  }
};
```

## 3\. Frontend Entegrasyonu: NotificationBell Bileşeni
