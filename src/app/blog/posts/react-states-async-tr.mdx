🧠 **React'te State Güncellemeleri Asenkron, Ama Promise Değil!**
React ile çalışan birçok geliştirici bunu zamanla fark eder, ancak başlangıçta kafa karıştırıcı olabilir:
`setState` (veya `useState` ile `setX`) fonksiyonları **asenkron olarak çalışır, ancak Promise döndürmez.**

Bu ne anlama geliyor?

```js
const [count, setCount] = useState(0);

setCount(count + 1);
console.log(count); // Hala eski değer!
```

Yukarıdaki örnekte, `count` değerinin hemen arttığını düşünebiliriz, ancak React bu güncellemeyi toplu halde işler ve bir sonraki render için saklar. Yani `console.log(count)` hala eski değeri yazdırır. Bu bize şunları gösterir:

➡️ `setState` tetiklenir ancak hemen uygulanmaz.
➡️ Promise gibi `.then()` kullanamayız.
➡️ Güncellenmiş state'e erişmek istiyorsak, `useEffect` gibi yöntemleri veya callback ile state fonksiyonunu kullanmamız gerekir.

Örneğin:

```js
useEffect((() => {
 console.log("Count değişti:", count);
}, [count]);
```

veya

```js
setCount(prev => prev + 1);
```

Dolayısıyla **asenkron ama promise değil** ifadesi burada devreye girer. React, state'i kendi iç planlamasına göre günceller, ancak bize bir promise vermez. 🔁

Bu farkı bilmek, özellikle form işlemlerinde, animasyonlarda veya state'e bağımlı business logic'te hata yapmamak için çok önemlidir. 👨‍💻
